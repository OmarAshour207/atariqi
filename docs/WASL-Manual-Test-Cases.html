Version: 1.0  |  Date: August 2026  |  Type: Manual testing (no automation)

WASL (Ministry of Transport) integration covering driver registration, eligibility, trip registration, location sync, province sync, scheduled jobs, and dashboard flows.

Test Prerequisites

Requirement
WASL API credentials configured in .env (RAFQNI_CLIENT_KEY, RAQFNI_APP_ID, RAQFNI_APP_KEY, RAQNI_API_URL)
WASL_ENABLED=true for live integration tests
Test driver with valid Saudi identity_number and vehicle sequence_number in ministry system
Test driver with known WASL rejection (for negative tests)
Admin account for dashboard approval flows
Passenger account for trip completion and rating
Access to storage/logs/wasl/ for verification
Artisan CLI access for scheduled command tests
Important: All test cases are designed for manual execution. Use the mobile app, dashboard, Postman, browser, or Artisan CLI as indicated in each test case. Verify results in the database, API responses, and log files.

1. WASL Integration Overview

Atariqi integrates with the Saudi Ministry of Transport WASL dispatching platform (Rabet API). Integration is controlled by WASL_ENABLED in .env. All WASL API calls are logged to storage/logs/wasl/.

WASL ServiceInternal MethodExternal API
5.1 Driver RegistrationWaslService::registerDriver()POST /api/dispatching/v2/drivers
5.2 Driver EligibilityWaslService::checkDriverEligibility()POST /api/dispatching/v2/drivers/eligibility
5.4 Trip RegistrationWaslService::storeTrip()POST /api/dispatching/v2/trips
5.6 Current LocationWaslService::updateCurrentLocations()POST /api/dispatching/v2/locations
5.7 Province InquiryWaslService::inquireProvinces()GET /api/dispatching/v2/trips/province-inquiry

2. Driver Registration (WASL 5.1)

Endpoint: POST api/driver/register

Route name: Driver App Registration

Note: Triggered automatically after successful local driver creation via RegisterController.

Test Case 1: Successful Registration with WASL

Objective: New driver registered locally and sent to WASL

Steps:

  1. Submit complete driver registration payload with valid identity_number, sequence_number, car details, and images
  2. Ensure WASL_ENABLED=true and valid API credentials
  3. Check response and logs

Expected Result:

Returns 200 with success message about registration review. User, driver_info, driver_car, and free package created. WASL registration API called. Entry logged in storage/logs/wasl/.

Test Case 2: WASL Rejection During Registration

Objective: WASL returns INVALID eligibility

Steps:

  1. Register driver with data that fails WASL validation (e.g. expired license, invalid vehicle)
  2. Submit registration

Expected Result:

Transaction rolled back OR error returned with translated WASL rejection message (e.g. "Driver license is expired"). No partial user record if exception thrown before commit.

Test Case 3: Duplicate Driver/Vehicle on WASL

Objective: DRIVER_VEHICLE_DUPLICATE code

Steps:

  1. Register driver already registered in WASL
  2. Submit registration

Expected Result:

Error: "Driver or vehicle already registered". Registration fails.

Test Case 4: WASL Disabled

Objective: Integration turned off

Steps:

  1. Set WASL_ENABLED=false in .env
  2. Submit valid driver registration

Expected Result:

Local registration succeeds. WASL API call skipped (no external request). Driver approval remains pending (0).

Test Case 5: Missing Identity Number

Objective: Required for WASL

Steps:

  1. Attempt registration without identity_number field
  2. Submit

Expected Result:

Validation error 422 on identity_number (required, unique).

Test Case 6: Missing Sequence Number

Objective: Required for vehicle

Steps:

  1. Submit registration without sequence_number
  2. Submit

Expected Result:

Validation error 422 on sequence_number.

Test Case 7: WASL API Unreachable

Objective: Network/API failure

Steps:

  1. Simulate WASL API timeout or 500 error during registration
  2. Submit valid registration

Expected Result:

Registration fails with exception message. DB transaction rolled back. Error logged to wasl channel.

3. Driver Eligibility Check (WASL 5.2)

Note: Not a public API endpoint — invoked internally by dashboard and scheduled jobs.

Objective: Driver and vehicle eligible

Steps:

  1. Use approved driver with valid identity_number in ministry system

Response parsed as is_valid=true. display_status="Valid". Driver and vehicle expiry dates shown if returned.

is_valid=false. Message includes "Vehicle model is older than 5 years".

Steps:

  1. Use driver failing criminal record check
  2. Run eligibility check

Expected Result:

is_valid=false. Appropriate translated rejection message displayed.

Objective: Cannot check without ID

Steps:

  1. Attempt eligibility check for driver without identity_number

Test Case 7: Multiple Rejection Reasons

4. Trip Registration (WASL 5.4)

Endpoint: POST api/drivers/rate

Route name: Passenger Rates Driver (triggers WASL trip store)

Note: WASL trip registration is triggered after passenger rates the driver, not at trip start.

Test Case 1: Successful Trip Registration

Objective: Completed trip sent to WASL

Steps:

  1. Complete an immediate/daily/weekly trip
  2. Passenger submits rating via api/drivers/rate with valid trip_id, type, and rate
  3. Check wasl logs

Expected Result:

Rating saved locally. storeTrip() called. WASL POST /api/dispatching/v2/trips succeeds. Trip data logged in storage/logs/wasl/. Response: "Updated successfully".

Test Case 2: Trip Not Found

Objective: No matching ride record

Steps:

  1. Submit rating with invalid trip_id
  2. Submit

Expected Result:

Rating may fail or trip registration skipped. No WASL call for missing trip.

Test Case 3: WASL Trip Registration Failure

Objective: WASL rejects trip data

Steps:

  1. Rate a trip with incomplete WASL-required data (missing province, invalid timestamps)
  2. Submit rating

Expected Result:

Rating saved locally. WASL error logged but rating response still returns success (error caught silently in ImmediateDriverController). Check storage/logs/wasl/ and laravel.log.

Test Case 4: Provinces Not Synced

Objective: Missing provinceId resolution

Steps:

  1. Attempt trip registration when wasl_provinces table is empty
  2. Complete and rate a trip

Expected Result:

WASL error: "WASL provinces are not synced. Run: php artisan wasl:sync-provinces" OR province resolution failure logged.

Test Case 5: WASL Disabled

Objective: Integration off

Steps:

  1. Set WASL_ENABLED=false
  2. Rate a completed trip

Expected Result:

Rating saved. storeTrip() returns null immediately. No WASL API call.

Test Case 6: Invalid Trip Type

Objective: Unsupported type parameter

Steps:

  1. Submit rating with invalid type value
  2. Submit

Expected Result:

Appropriate validation or lookup error.

Test Case 7: Verify Trip Payload Fields

Objective: Data integrity

Steps:

  1. Complete trip with known origin/destination cities
  2. Rate trip and inspect wasl log payload

Expected Result:

Payload includes driverIdentityNumber, vehicleSequenceNumber, timestamps, coordinates, and trip cost fields per UpdateTripDataResource.

Endpoint: Artisan php artisan wasl:sync-driver-locations

Route name: Scheduled Location Sync Command

Note: Scheduled every minute via Laravel scheduler.

Test Case 1: Successful Sync

Objective: Send locations to WASL

Steps:

  1. Ensure drivers with is-receiving-rides=true OR on ongoing trips have stored lat/lng, identity_number, sequence-number
  2. Run: php artisan wasl:sync-driver-locations
  3. Check console output and wasl logs

Expected Result:

Console: "Sent N driver location(s) to WASL." WASL POST /api/dispatching/v2/locations called with locations array. hasCustomer=true for ongoing trip drivers, false for available drivers.

Test Case 2: Dry Run Mode

Objective: Preview without sending

Steps:

  1. Run: php artisan wasl:sync-driver-locations --dry-run --show-details

Expected Result:

Console shows diagnostics (ongoing driver IDs, receiving rides IDs, collected locations). No WASL API call made. Message: "Dry run: would send N driver location(s) to WASL."

Test Case 3: No Locations Collected

Objective: Nothing to send

Steps:

  1. Ensure no drivers are receiving rides and no ongoing trips with stored locations
  2. Run command

Expected Result:

Console: "No driver locations collected. Nothing sent to WASL." Exit code 0.

Test Case 4: Missing identity_number or sequence-number

Objective: Driver skipped

Steps:

  1. Driver receiving rides but missing identity_number or sequence-number
  2. Run command with --show-details

Expected Result:

Driver listed in diagnostics with [missing: identity_number] or [missing: sequence-number]. Location NOT included in WASL payload.

Test Case 5: WASL Disabled

Objective: Integration off

Steps:

  1. Set WASL_ENABLED=false
  2. Run command

Expected Result:

Console: "WASL is disabled (WASL_ENABLED=false)." Exit code 0. No API call.

Test Case 6: WASL API Failure

Objective: External error

Steps:

  1. Simulate WASL location API returning error
  2. Run command

Expected Result:

Console error message. Logged to storage/logs/wasl/. Exit code 1 (FAILURE).

Test Case 7: Scheduled Execution

Objective: Cron job

Steps:

  1. Verify schedule in app/Console/Kernel.php (everyMinute)
  2. Wait for scheduler or run php artisan schedule:run

Expected Result:

Command executes automatically every minute when scheduler is active.

7. Daily Eligibility Check (Scheduled Job)

Endpoint: Artisan php artisan drivers:check-wasl-eligibility

Route name: Daily Eligibility Command

Note: Scheduled daily at 02:00 via Laravel scheduler.

Test Case 1: Driver Becomes Ineligible

Objective: Approval changed to 4

Steps:

  1. Start with approved driver (approval=1) whose WASL eligibility expires or becomes invalid
  2. Run command
  3. Check driver record

Expected Result:

Driver approval updated to 4. reject-reason set to WASL rejection message. Driver blocked from trip operations (ChecksDriverWaslStatus trait).

Test Case 2: Driver Becomes Eligible Again

Objective: Approval restored from 4 to 0

Steps:

  1. Driver with approval=4 becomes valid in WASL again
  2. Run command

Expected Result:

Driver approval updated to 0. reject-reason cleared. Driver can proceed with re-approval flow.

Test Case 3: No Change — Still Valid

Objective: Approved driver remains valid

Steps:

  1. Run command for eligible approved driver

Expected Result:

No approval change. Driver remains approval=1.

Test Case 4: Skip Drivers Without Identity

Objective: Missing identity_number

Steps:

  1. Driver without identity_number in driver_info
  2. Run command

Expected Result:

Driver skipped silently. No API call.

Test Case 5: WASL API Error During Check

Objective: Transient failure

Steps:

  1. Simulate WASL API error for a driver
  2. Run command

Expected Result:

Driver skipped (is_valid=null or api_error). No approval change. Error logged to wasl channel.

Test Case 6: Scheduled Daily Run

Objective: Cron at 02:00

Steps:

  1. Verify schedule in Kernel.php: dailyAt 02:00
  2. Run php artisan schedule:run at scheduled time

Expected Result:

Command processes all drivers with approval in [0,1,4] and identity_number set.

Test Case 7: Driver App Block After approval=4

Objective: Operational block

Steps:

  1. Set driver approval=4 via daily check
  2. Driver attempts to start service or accept trip in app

Expected Result:

403 error: s_abshir_update_required with message about Absher update required.
